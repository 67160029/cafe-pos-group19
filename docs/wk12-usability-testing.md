# WK12 บันทึกผลการตรวจระบบและ Usability Testing

วิชา: การวิเคราะห์และออกแบบระบบ (Systems Analysis and Design)  
โครงงาน: Cafe POS & Smart Inventory System (กลุ่ม 19)

> **หมายเหตุเรื่องที่มาของข้อมูล:** ส่วนผลที่บันทึกในรอบนี้มาจาก AI (OpenAI Codex) เปิดและใช้งานหน้าเว็บจริงที่ `http://localhost:3000/` พร้อมตรวจข้อมูลสาขาและเมนูในฐานข้อมูล ไม่ใช่การทดสอบโดยผู้ใช้ที่เป็นคน และไม่มี think-aloud ของมนุษย์ AI ไม่แต่งคำพูดหรือพฤติกรรมแทนผู้ใช้ ผลนี้จึงเป็นเพียงการตรวจ flow ทางเทคนิคเบื้องต้น ไม่ใช่หลักฐาน usability testing ตาม workshop และไม่ควรนับแทน session กับผู้ทดสอบจริง

การกดยืนยันออเดอร์จะสร้างรายการในฐานข้อมูลและตัดสต็อก จึงไม่ได้กดปุ่มนี้ระหว่างตรวจระบบ รอบทดสอบกับผู้ใช้จริงควรใช้ฐานข้อมูลทดสอบหรือข้อมูลที่เตรียมไว้และล้างคืนได้

## 1. Task ที่ใช้ตรวจ

เป้าหมายเหล่านี้ใช้ตรวจการทำงานของ UI โดย AI ไม่ใช่ task session ของผู้ใช้จริง

| Task | เป้าหมาย | ประเภท | สถานะ |
|---|---|---|---|
| Task 1 | เพิ่ม Latte 1 แก้ว เพิ่มจำนวนเป็น 2 แล้วนำรายการออกจากออเดอร์ | ตรวจตะกร้าและยอดรวม | ตรวจได้ |
| Task 2 | เปลี่ยนจาก Branch 1 ไป Branch 2 เพื่อดูการโหลดเมนูและสถานะตะกร้า | ตรวจการเปลี่ยนสาขา | ตรวจได้ แต่ Branch 2 ไม่มีเมนู |
| Task 3 | ลองเลือกเมนูที่สต็อกเป็น 0 | ตรวจ error path | ตรวจไม่ได้ เพราะไม่มีเมนูสต็อก 0 ในฐานข้อมูล |

## 2. บันทึกการทำ Task และสิ่งที่ระบบแสดง

### Task 1 — เพิ่มและนำ Latte ออกจากออเดอร์

| ลำดับ | สิ่งที่ทำผ่านหน้าเว็บ | สิ่งที่ระบบแสดงจริง |
|---|---|---|
| 1 | เปิดหน้า POS ที่ Branch 1 | โหลดเมนูสำเร็จ แสดง Americano (คงเหลือ 19) และ Latte (คงเหลือ 15); ตะกร้า 0 รายการ; ปุ่มยืนยันออเดอร์ปิดอยู่ |
| 2 | เพิ่ม Latte ลงออเดอร์ | ตะกร้าแสดง Latte 1 รายการ ยอด ฿70.00 และข้อความแจ้งว่าเพิ่มเมนูแล้ว |
| 3 | เพิ่มจำนวน Latte อีก 1 | จำนวนเป็น 2 รายการ ยอดปรับเป็น ฿140.00 |
| 4 | นำ Latte ออกจากออเดอร์ | ตะกร้ากลับเป็น 0 รายการ ยอด ฿0.00 และปุ่มยืนยันออเดอร์ปิดอยู่ |

ผลการตรวจทางเทคนิค: การเพิ่มจำนวน การคำนวณยอด และการนำรายการออกทำงานตามที่คาด ไม่ได้ทดสอบการชำระเงินหรือยืนยันออเดอร์ และไม่มีคำพูด think-aloud เนื่องจากไม่มีผู้ทดสอบที่เป็นคน

### Task 2 — เปลี่ยนสาขา

| ลำดับ | สิ่งที่ทำผ่านหน้าเว็บ | สิ่งที่ระบบแสดงจริง |
|---|---|---|
| 1 | เปลี่ยนรหัสสาขาจาก 1 เป็น 2 | ตะกร้าถูกล้าง และหน้าแสดง “ยังไม่มีเมนูในสาขานี้”; ปุ่มยืนยันออเดอร์ปิดอยู่ |
| 2 | ตรวจรายการสาขาในฐานข้อมูล | พบ Branch 1 เท่านั้น จึงไม่มีเมนูใน Branch 2 ให้ตรวจต่อ |

ผลการตรวจทางเทคนิค: UI ตอบสนองต่อการเปลี่ยนสาขาและไม่คงรายการจากสาขาเดิมไว้ แต่ไม่สามารถตรวจการเลือกเมนูข้ามสาขาได้เพราะไม่มีข้อมูลสาขาที่ 2

### Task 3 — เมนูหมดสต็อก

ไม่ได้ทดลองกดการ์ดเมนูหมดสต็อก เพราะข้อมูลจริงของ Branch 1 มีสต็อกเป็นบวกทั้ง Americano และ Latte จึงไม่มีหลักฐานว่าหน้าจอแสดงหรือจัดการ error path นี้อย่างไร

## 3. รายการ Usability Issue

รอบนี้ไม่มีการสังเกตจากผู้ใช้ใหม่ จึงยังไม่มี usability issue ที่ยืนยันได้จาก think-aloud การขาดข้อมูลสำหรับ Branch 2 และเมนู stock 0 เป็นข้อจำกัดของชุดข้อมูลทดสอบ ไม่ใช่ issue ของ UI

| # | ข้อค้นพบ | ประเภท | Severity | สถานะ |
|---|---|---|---|---|
| — | ยังไม่มี issue ที่ยืนยันจาก session ของผู้ใช้จริง | ยังประเมินไม่ได้ | ยังไม่จัดระดับ | รอทดสอบกับคนจริง |

## 4. การแก้ไขและแผนก่อนทดสอบกับผู้ใช้จริง

| หัวข้อ | การดำเนินการ |
|---|---|
| ชุดข้อมูลทดสอบ | เตรียมฐานข้อมูลทดสอบที่มีเมนูขายได้ เมนู stock 0 และอีกสาขาที่มีเมนูต่างจาก Branch 1 หรือปรับ task ให้ตรงกับข้อมูลที่เตรียม |
| การยืนยันออเดอร์ | ใช้ข้อมูลทดสอบที่ล้างคืนได้ เพราะ POST order จะสร้างออเดอร์และตัดสต็อก |
| ผู้ทดสอบและผู้สังเกตการณ์ | ให้คนที่ไม่คุ้นกับหน้า POS ทำ task; ผู้สังเกตการณ์จดคำพูดและพฤติกรรมโดยไม่ชี้นำ |
| บันทึกผลจริง | เติมเวลา ผลสำเร็จ/ไม่สำเร็จ เหตุการณ์และคำพูดจริงในตารางด้านล่าง แล้วจัด severity จากผลกระทบ |
| แก้ไข | หลังพบ Critical/Major ให้ระบุ issue ที่เลือกแก้ ไฟล์หรือ wireframe ที่เปลี่ยน และผลทดสอบซ้ำจริง |


## 5. สรุปสำหรับทีม

AI ตรวจ flow ทางเทคนิคของหน้า POS ได้บางส่วน: เพิ่ม Latte, เปลี่ยนจำนวน, คำนวณยอด, นำรายการออก และเปลี่ยนไปสาขาที่ไม่มีเมนู โดยไม่ส่งออเดอร์หรือแก้ข้อมูลในฐานข้อมูล ไม่พบปัญหาเชิงการทำงานใน flow ที่ตรวจ แต่ยังตรวจ error path สต็อกหมด การเปลี่ยนไปสาขาที่มีเมนู และการยืนยันชำระเงินจริงไม่ได้ รอบนี้ไม่มีผู้ทดสอบที่เป็นคน จึงยังสรุป usability issue หรือ severity ไม่ได้ ขั้นต่อไปคือเตรียมข้อมูลทดสอบและทำ session กับผู้ใช้จริงอย่างน้อยหนึ่งคน
